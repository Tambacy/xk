# 学校选课助手 v0.3.9

自动盯课余量、按预定时间抢课。全程用真实 Chromium 浏览器操作，不发送脚本化的后台请求。

> ⚠️ 仅供本人选课使用。请遵守学校相关规定，合理设置监听间隔。

## 下载

| 文件 | 说明 |
|---|---|
| `XkHelper-Setup-0.3.9.exe` | 安装包，推荐。自包含（内置一整个 Chromium），装完即用 |
| `XkHelper-v0.3.9-source.zip` | 源码，想自己改或自己构建就下这个 |

## 相比 v0.3.8

### 修复

- **运行监控页的「已运行」一直停在 00:00:00，根本不走**

  调度器在一轮运行里**第一件事**就是推一个 `state=idle`（浏览器刚起来、
  还没进入监听），而界面把「不在运行中的状态」一律当作「已停下」处理 ——
  停表的同时把计时起点也清掉了。等真正进入「监听中」时，表虽然在走、
  起点却已经没了，于是永远显示 `00:00:00`

  现在只有**真正结束**（已完成 / 已停止 / 出错了）才停表并冻结；
  `idle` 归入「正在跑」，计时起点只由「开始运行」设定，别的状态一律不动它

  > 这是 v0.3.1 修「停止后还在累加」时引入的，从 v0.3.1 到 v0.3.8 都在

### 改进

- 界面回归新增「已运行走字」检查，**按调度器真实的推送顺序**驱动
  （idle → preparing → monitoring）。只推 monitoring 是测不出这个 bug 的 ——
  第一版 A/B 就因为这个漏掉了，重做才复现出来

## 相比 v0.3.7

### 改进

- **运行监控页的「目标课程」改为整体重绘**，不再逐条改文字。
  卡片被明确定义为「清单 + 最近一次轮询结果」的渲染结果：
  清单是唯一的事实来源，任何时候都按它整张重画
  - 停止后重新开始，卡片自动回到清单原文，不带上一轮的课余量
  - 同一份状态重复推送是幂等的：内容不变、行数不增长

## 相比 v0.3.6

### 修复

- **运行监控页的「目标课程」会出现一门根本没加过的课**。清单里只要有
  「要退的课」排在「要抢的课」前面，界面就会把那条「退」的文字换成
  「抢」那门课的内容 —— 凭空冒出一个「退　X」，和真正的「抢　X」并排

## 相比 v0.3.5

### 修复

- **同一门课可以同时出现在「要抢的课」和「要退的课」里**，运行时真的会
  「先把它退掉、再把它抢回来」。两个入口都会拦，开始运行前还会再检查一遍

## 相比 v0.3.4

## 相比 v0.3.3

- 停止后「距下次检查」会停留在最后一个数字上，现在立即清为横杠

## 相比 v0.3.2

- 时间冲突的提示补上了后果说明：抢到时程序会**自动退掉**撞时间的那门已选课程

### 改进

- 「认课程」的判断抽成公共函数，校验冲突与运行时挑让位课改用同一套

## 相比 v0.3.1

  读回配置，确认页拿到的一直是默认值

### 改进

- 确认页不再写死「夜间静默」这句说明

## 相比 v0.3.0

## 相比 v0.2.0（v0.3.0 以来的累积改动）

### 改进

- **界面整体改版**。主色由紫色改为淡紫，五个页面统一了配色、字号层级与间距
- 窗口顶部与登录页新增**夜空天幕**：极光、星点与同心弧纹，随窗口缓慢漂移
- 登录页由居中单卡片改为「品牌区 + 表单」分栏
- 步骤进度由互不相连的标签改为带连接线的步骤导轨
- **页面切换改为粒子渐变揭示**：新页从中心化开，边缘跑一圈粒子
- **按钮增加粒子**：悬停与点击时沿按钮边缘溅出，并受重力回落
- 课程卡片增加左侧状态色条，校验状态可直接看出
- 顶部天幕带高度由 176px 压到 142px，操作区域不再被顶到下面
- `docs/使用说明.html` 改为**翻页式演示稿**：一页一屏、19 屏，每屏独立背景

### 构建

- 应用图标改用与界面一致的主色，并补充窗口图标设置
- `XkHelper.exe` 补齐产品名与版本号
- 新增发布前凭据审计脚本，并由发布脚本在上传前强制执行

### 未包含

- 选课、登录、调度逻辑无改动
- 未引入任何新的第三方依赖（动效与背景均使用 Qt 自带能力与 CSS/SVG）

## 安装使用

1. 双击安装包，一路下一步（不需要管理员权限）
2. 输入学号和密码登录
3. 选择运行模式
4. 填写课程信息并添加到清单，程序会自动去教务系统查证
5. 下一步 → 开始运行

首次登录若被要求二次验证，按界面提示操作即可。建议在「是否登记信任设备」一步选「是」。
